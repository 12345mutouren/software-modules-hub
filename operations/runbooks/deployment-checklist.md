# Deployment Checklist

每次发布前后使用这个清单。

## Before Deployment

- [ ] 确认发布目标环境。
- [ ] 确认变更范围。
- [ ] 确认是否包含数据库迁移。
- [ ] 确认是否包含权限或安全变化。
- [ ] 确认是否包含支付、订单、登录等关键路径变化。
- [ ] 测试通过。
- [ ] E2E 关键路径通过。
- [ ] 备份已完成或确认不需要备份。
- [ ] 回滚方案明确。

## Deployment

- [ ] 部署应用代码。
- [ ] 执行数据库迁移。
- [ ] 验证环境变量。
- [ ] 验证健康检查。
- [ ] 验证关键页面。
- [ ] 验证关键 API。
- [ ] 验证日志和错误监控。

## After Deployment

- [ ] 观察错误率。
- [ ] 观察响应时间。
- [ ] 观察登录、注册、支付或核心业务指标。
- [ ] 检查后台任务。
- [ ] 检查 webhook 是否正常。
- [ ] 更新变更日志。
- [ ] 必要时通知用户或内部团队。

## Rollback

触发回滚的常见条件：

- 登录或注册大面积失败。
- 支付或订单异常。
- 数据库迁移错误。
- 错误率持续升高。
- 核心页面不可访问。

回滚动作：

1. 暂停继续发布。
2. 切回上一版本应用。
3. 判断数据库迁移是否需要回滚或补丁。
4. 验证健康检查和关键路径。
5. 记录事故和复盘。
