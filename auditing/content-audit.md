# Content Audit

## Cadence

- After every new phase.
- Before every release.
- Quarterly for repository freshness.

## Checks

| Area | Check |
| --- | --- |
| Module docs | Categories, examples and checks still match the 10-module model |
| GitHub repository index | Projects are still relevant and correctly classified |
| Templates | App templates still map to 10 modules |
| Case studies | Real project notes are not misleading or stale |
| Reference | Glossary and comparisons do not contradict deeper docs |
| Showcase | Public summaries match current repository content |

## Decision

Each audit should end with one of:

- Pass.
- Pass with follow-up.
- Blocked until correction.
