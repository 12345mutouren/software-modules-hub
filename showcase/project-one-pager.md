# Project One-Pager

## Project

Software Modules Hub 是一个完整软件模块知识库。

它把一个现代软件拆成 10 个核心层：产品、账号、数据库、后端、前端、安全、运维、测试、商业运营和文档，并继续补充示例、模板、案例、架构、决策、学习、速查和发布材料。

## Audience

| Audience | What They Get |
| --- | --- |
| 初学者 | 知道完整软件到底包含哪些部分 |
| 独立开发者 | 从想法整理到项目启动和发布 |
| 全栈工程师 | 对照模块、模板、架构图和 Runbook 查漏补缺 |
| 技术负责人 | 用 checklist、ADR、权限矩阵和风险登记统一团队理解 |
| 学习型团队 | 用学习路线、练习和毕业项目组织训练 |

## Problem

很多人学习软件开发时会先接触单个功能，例如登录、数据库、页面、支付或部署。

真正做一个完整软件时，问题会变成：

- 这个软件给谁用？
- 用户怎么注册、登录和找回账号？
- 数据怎么建模、搜索、缓存和备份？
- API、权限、文件、通知和定时任务怎么组织？
- 前端、后台、移动端或桌面端该怎么选？
- 安全、测试、部署、监控、支付、运营和文档怎么补齐？

这个仓库的作用是把这些问题放到同一张结构图里。

## What Is Included

| Layer | Assets |
| --- | --- |
| Knowledge map | 10 个模块文档、分类法、GitHub 仓库索引 |
| Runnable example | 一个无第三方依赖的小型全栈示例和测试 |
| Complete templates | SaaS、管理后台、电商、内容社区、AI 知识库、企业内部工具 |
| Real project studies | Cal DIY、Plane、Twenty、Supabase、Appwrite、Dub |
| Architecture and operations | Mermaid 架构图、部署、备份、事故、安全发布、监控 Runbook |
| Decision and kickoff | 选型决策树、ADR、权限矩阵、API 合同、风险登记等模板 |
| Learning system | 角色路线、30 天计划、练习、毕业项目、自评 |
| Reference system | 总索引、术语表、产物地图、技术对比、仓库评估、常见坑 |
| Publishing layer | 一页概览、仓库导览、发布手册、维护手册、分享摘要 |

## What It Is Not

- 不是一个已经接入真实支付、短信、对象存储和生产数据库的商业系统。
- 不是某个框架的单一脚手架。
- 不是对所有 GitHub 项目的实时排名。
- 不是替代安全审计、法律合规或生产运维的最终结论。

## Best First Use

1. 读 [modules/README.md](../modules/README.md) 建立完整软件的 10 层框架。
2. 跑 [full-stack-mini-app](../examples/full-stack-mini-app/README.md) 理解模块如何落到代码。
3. 用 [templates/complete-apps](../templates/complete-apps/README.md) 选择一个产品类型。
4. 用 [project-kickoff](../project-kickoff/README.md) 写出自己的第一版项目计划。
5. 用 [quality](../quality/README.md) 检查仓库结构和示例是否仍然健康。
