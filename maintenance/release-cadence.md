# Release Cadence

## Version Pattern

| Version | Meaning |
| --- | --- |
| `1.0.x` | Small fixes |
| `1.1.x` | Generator, runnable template or docs-site improvements |
| `1.2.x` | New app categories or deeper code examples |
| `2.0.0` | Major model or repository structure change |

## Release Steps

1. Run `npm test`.
2. Update `CHANGELOG.md`.
3. Update release notes.
4. Commit and push.
5. Confirm GitHub Actions.
6. Create GitHub Release.

## Maintenance Rule

Do not add a new phase without checklist, audit, verifier coverage and changelog entry.
