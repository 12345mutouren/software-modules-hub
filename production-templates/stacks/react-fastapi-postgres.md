# React + FastAPI + PostgreSQL

## Best Fit

- AI knowledge bases.
- Data-heavy internal tools.
- Reporting dashboards.
- Systems that benefit from Python ecosystem libraries.

## Services

| Service | Responsibility |
| --- | --- |
| `web` | React SPA, admin UI, search UI and upload flows |
| `api` | FastAPI HTTP API, validation, permissions and business services |
| `worker` | Document parsing, embeddings, scheduled reports and provider retries |
| `postgres` | Core business data, users, permissions and audit logs |
| `redis` | Cache, jobs, rate limits and temporary tokens |
| `vector-store` | Semantic search and retrieval when needed |
| `object-storage` | Uploaded documents, exports and generated files |

## Suggested Directory

```text
apps/web
apps/api
apps/worker
packages/contracts
packages/config
infra
docs
```

## Default Decisions

| Area | Default |
| --- | --- |
| API contracts | OpenAPI generated by FastAPI |
| Validation | Pydantic models |
| Database | PostgreSQL with migrations |
| Background work | Queue worker for parsing, embeddings and reports |
| Tests | Python API tests plus frontend smoke tests |

## Risks

- Long-running AI jobs should not block API requests.
- Vector search must respect workspace and document permissions.
- File parsing failures need retry and user-visible status.
