# Exercises

这些练习按模块设计。每个练习都应该产出一个文件、表格、测试或代码改动。

## Product Layer

Exercise:

- 选择一个软件想法。
- 写 product brief。
- 列出用户角色、核心流程、非目标和成功指标。

Done when:

- 能明确什么是第一版必须做，什么明确不做。

## Account System

Exercise:

- 为你的项目选择登录方式和注册方式。
- 写权限矩阵。
- 说明 Session/JWT/Cookie 怎么选。

Done when:

- 每个角色能访问什么、不能访问什么都写清楚。

## Database Layer

Exercise:

- 画核心数据表。
- 标出主键、外键、唯一约束和索引。
- 说明哪些数据进入缓存、搜索、对象存储或向量库。

Done when:

- 能解释每张表为什么存在。

## Backend System

Exercise:

- 写 8-12 个关键 API。
- 标出每个 API 的 Auth、权限、输入、输出和错误。

Done when:

- API 合同能指导前端和测试。

## Frontend/Client

Exercise:

- 列出页面清单。
- 为每个页面写加载、空状态、错误和无权限状态。

Done when:

- 用户从进入软件到完成核心任务的界面路径清楚。

## Security

Exercise:

- 用 security review 模板审查你的项目。
- 至少找出 5 个风险并写缓解策略。

Done when:

- 能说明最可能的数据泄露、越权和滥用风险。

## Operations/Deployment

Exercise:

- 写 local、staging、production 环境表。
- 写发布和回滚步骤。
- 写备份恢复演练步骤。

Done when:

- 你能说明服务坏了、数据库坏了、发布坏了分别怎么办。

## Testing

Exercise:

- 写单元、API、E2E、权限、安全和性能测试计划。
- 为一个关键流程写出测试步骤。

Done when:

- 测试计划覆盖登录、核心业务、权限和发布风险。

## Business/Operations

Exercise:

- 如果是商业产品，写计划、订单、支付、发票和客服流程。
- 如果不是商业产品，写反馈、数据统计、内容审核或运营流程。

Done when:

- 运营人员知道如何处理用户问题和关键业务状态。

## Documentation

Exercise:

- 写产品说明、用户文档、API 文档、部署文档、FAQ 的目录。

Done when:

- 新用户、新开发者和管理员都能找到入口。
