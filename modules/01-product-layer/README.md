# 01 产品层

产品层回答最根本的问题：这个软件解决什么问题，给谁用，用户为什么愿意反复使用。

如果产品层不清楚，后面的账号、数据库、后端、前端、安全和运营都会变成没有方向的堆功能。

## 核心能力

- 定义软件目标：解决什么问题，避免解决不存在的问题。
- 定义用户类型：谁在使用，谁在管理，谁在付费，谁受影响。
- 定义核心功能：用户真正来完成的任务。
- 定义使用流程：用户从进入软件到完成目标的路径。
- 定义页面/界面：用户会看到哪些入口、页面和状态。

## 类别地图

| 类别 | 说明 | 常见产物 |
| --- | --- | --- |
| 目标定义 | 软件解决什么问题，为什么值得做 | 产品愿景、问题陈述、成功标准 |
| 用户类型 | 识别不同角色和权限 | 游客、普通用户、会员、管理员、企业用户、客服、运营 |
| 核心功能 | 用户真正使用的能力 | 发帖、下单、聊天、管理库存、生成文档 |
| 使用流程 | 用户完成任务的路径 | 用户旅程、流程图、状态图 |
| 页面/界面 | 软件的可见结构 | 主页、登录页、注册页、用户中心、功能页、设置页、后台管理页 |
| 信息架构 | 内容如何组织 | 导航、菜单、列表、详情页、搜索入口 |
| 成功指标 | 如何判断产品有效 | 激活率、留存率、转化率、任务完成率、付费率 |
| 边界定义 | 什么不做 | 非目标、延期范围、风险假设 |

## 用户类型

| 用户类型 | 典型能力 | 需要关注 |
| --- | --- | --- |
| 游客 | 浏览公开内容、试用部分功能 | 引导、转化、匿名数据 |
| 普通用户 | 使用核心功能、管理个人资料 | 易用性、数据归属、隐私 |
| 会员 | 使用付费能力、管理订阅 | 权益、到期、续费、发票 |
| 管理员 | 管理用户、内容、配置 | 权限、审计、误操作恢复 |
| 企业用户 | 团队协作、组织管理、SSO | 多租户、角色、合规 |
| 客服 | 处理用户问题 | 查询、工单、操作边界 |
| 运营 | 配置活动、内容审核、数据分析 | 统计、分群、推荐、审核 |

## 常见页面/界面

- 主页：首页、产品入口、公开内容入口。
- 登录页：账号密码、验证码、第三方登录、找回密码。
- 注册页：开放注册、邀请注册、企业注册、付费注册。
- 用户中心：资料、头像、邮箱、手机号、偏好、账单。
- 核心功能页：软件主要任务所在的页面。
- 设置页：账号设置、团队设置、通知设置、安全设置。
- 后台管理页：用户管理、内容管理、权限管理、数据统计。
- 错误和空状态页：404、无权限、无数据、加载失败。

## 常见流程

1. 用户进入软件。
2. 系统判断是游客、已登录用户、会员还是管理员。
3. 用户通过导航进入目标功能。
4. 用户创建、查询、修改或删除数据。
5. 系统返回结果、提示状态或触发通知。
6. 用户完成任务、退出、复购或进入下一个流程。

## 设计检查清单

- [ ] 是否明确软件解决的问题。
- [ ] 是否明确目标用户和非目标用户。
- [ ] 是否列出游客、用户、会员、管理员、企业、客服、运营等角色。
- [ ] 是否定义核心功能，而不是只列技术模块。
- [ ] 是否画出用户从进入到完成任务的流程。
- [ ] 是否列出所有关键页面和状态。
- [ ] 是否定义成功指标。
- [ ] 是否明确第一阶段不做什么。
