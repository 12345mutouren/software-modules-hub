# 模块总览

一个完整软件可以理解成 10 个互相协作的层级。它们不一定都要在第一天实现，但都应该被识别、取舍和记录。

## 10 大模块地图

| 编号 | 模块 | 解决的问题 | 常见产物 |
| --- | --- | --- | --- |
| 01 | 产品层 | 软件为谁解决什么问题 | 产品说明、用户角色、流程图、页面清单 |
| 02 | 账号系统 | 谁能进入系统，以什么身份使用 | 登录注册、用户资料、权限角色、账号安全 |
| 03 | 数据库层 | 数据存在哪里，如何组织和查询 | 数据库、数据表、ORM、迁移、备份 |
| 04 | 后端系统 | 业务逻辑如何运行 | API、服务、权限校验、定时任务、消息系统 |
| 05 | 前端/客户端 | 用户如何操作软件 | Web、App、桌面端、管理后台、交互状态 |
| 06 | 安全 | 如何防止数据和系统被滥用 | 加密、会话、防攻击、限流、审计、隐私 |
| 07 | 运维部署 | 软件如何上线并稳定运行 | 服务器、环境、CI/CD、监控、备份、灾难恢复 |
| 08 | 测试 | 如何证明软件按预期工作 | 单元测试、接口测试、E2E、权限测试、安全测试 |
| 09 | 商业/运营功能 | 软件如何服务商业和增长 | 支付、订单、会员、优惠券、客服、分析、审核 |
| 10 | 文档 | 如何让用户、开发者和管理员理解软件 | 产品文档、API 文档、部署文档、FAQ |

## 依赖关系

典型依赖顺序：

```text
产品层
  -> 账号系统
  -> 数据库层
  -> 后端系统
  -> 前端/客户端
  -> 安全
  -> 运维部署
  -> 测试
  -> 商业/运营功能
  -> 文档
```

实际项目里这些模块会交叉。例如账号系统依赖数据库，也影响安全、前端、后端和文档；支付系统依赖后端、数据库、安全、运维和客服流程。

## 建议阅读方式

- 想做产品：先读产品层、前端、商业运营、文档。
- 想做网页登录：先读账号系统、数据库、后端、前端、安全。
- 想做后台管理：先读账号系统、权限、数据库、后端、管理后台、测试。
- 想做能上线的软件：必须读安全、运维部署、测试、文档。
