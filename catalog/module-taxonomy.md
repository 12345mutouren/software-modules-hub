# 模块分类法

这个文件用于统一仓库里的分类口径，避免把不同性质的东西混在一起。

## 按软件层级分类

| 层级 | 说明 |
| --- | --- |
| 产品层 | 需求、目标用户、用户流程、页面结构 |
| 体验层 | 前端页面、移动端、桌面端、后台管理、交互状态 |
| AI 交互层 | Agent UI、Generative UI、上下文共享、人机确认 |
| 业务层 | 后端 API、业务规则、订单、会员、通知、定时任务 |
| 数据层 | 数据库、缓存、搜索、文件存储、数据表、迁移 |
| 身份层 | 登录、注册、用户资料、权限、组织、团队、SSO |
| 安全层 | 加密、会话、防攻击、限流、日志审计、隐私合规 |
| 运行层 | 部署、环境、监控、报警、备份、恢复、CI/CD |
| 质量层 | 测试、审计、性能、安全验证 |
| 知识层 | 文档、FAQ、操作手册、API 说明 |

## 按 GitHub 仓库类型分类

| 类型 | 判断标准 | 使用方式 |
| --- | --- | --- |
| library | 提供函数、组件或 SDK，通常被安装到项目里 | 学 API，接入项目 |
| framework | 提供项目骨架和运行规则 | 按框架方式开发 |
| starter | 已经组合多个模块，可作为新项目起点 | 克隆后改造 |
| platform | 可部署成独立服务 | 自托管或集成 |
| product-source | 真实产品源码 | 学模块组合和架构 |
| sample | 聚焦单个功能的演示 | 学最小实现 |
| tooling | 开发、部署、测试、监控工具 | 加入开发流程 |

## 按成熟度分类

| 成熟度 | 特征 | 适合场景 |
| --- | --- | --- |
| 学习型 | 文档清晰、功能聚焦、规模小 | 入门、理解概念 |
| 项目型 | 能直接接入真实项目 | 中小型项目 |
| 企业型 | 支持 SSO、审计、多租户、权限、合规 | 企业系统 |
| 平台型 | 自己就是一套服务 | 作为基础设施 |

## 选型原则

- 先明确模块目标，再选仓库。
- 先看是否长期维护，再看功能数量。
- 先找最贴近自己技术栈的方案。
- 如果只是学习，优先 sample 和 starter。
- 如果要做生产系统，必须同时考虑安全、测试、部署和文档。
