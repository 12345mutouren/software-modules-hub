# v2.3.0 - SQLite Database Adapter

Date: 2026-06-14

## Summary

This release adds a real SQL-backed database path to the backend foundation.

`packages/database` now includes a SQLite adapter using Node's built-in SQLite runtime. The same data, API and web admin layers can run on memory, JSON file storage or SQLite without changing their business logic.

## Added

- `createSqliteDatabase` adapter.
- SQL migration ledger stored in `__migrations`.
- SQL index metadata stored in `__indexes`, plus actual SQLite expression indexes over JSON-backed records.
- SQLite-backed table creation, insert, get, list, find, update and snapshot operations.
- SQLite transaction rollback.
- SQLite persistence tests for:
  - `packages/database`
  - `packages/data`
  - `packages/api`
  - `apps/web-admin-app`

## Updated

- Root version is now `2.3.0`.
- `apps/web-admin-app` uses SQLite automatically when `DATA_FILE` ends in `.sqlite`, `.sqlite3` or `.db`.
- Web admin docs now recommend:

```bash
DATA_FILE=.local/web-admin.sqlite npm --prefix apps/web-admin-app start
```

- Repository verification now requires SQLite adapter coverage.

## Verification

```bash
npm run test:database
npm run test:data-api
npm run test:web-admin
npm test
```

## Why It Matters

Professional backend foundations need a real SQL path. This release keeps the repository dependency-light while adding database behavior that is much closer to production engineering: SQL migrations, SQL-backed persistence, SQL indexes, transactions and restart-safe integration tests.
